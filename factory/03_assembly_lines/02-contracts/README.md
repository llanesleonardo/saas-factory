# Station: Contracts (per-app — repo root)

**“Contract” here** means **persisted engineering agreements** — not a legal document. They are the **authoritative configs + specs** under **`configs/apps/<app>/`** that bind *what we sell / scope* (Product IR), *how we stack it* (System IR), and *how we accept it* (Markdown specs / phases). Downstream stations (**gates, scaffold, validation**) consume these so work stays aligned without re-negotiating scope ad hoc.

Artifacts appear after **intake** (`../01-intake/`) ties an **order** to one or more **`productId`**s and you create or refresh Product IR, System IR, and specs (often via **`../06-gates/`** wizards).

**Per-order snapshot (binds an order folder to those configs):**  
`factory/01_production_planning/01_00_work_orders/<orderId>/contracts/<productId>/contract.json` — generated by **`mfg order validate`** / **`mfg order contracts`** (repo-relative paths into **`configs/apps/<productId>/`**).

**Canonical paths (not under `factory/`):**

- Product IR: `configs/apps/<app>/<app>.json`
- System IR: `configs/apps/<app>/app.stack.json`
- Specs + phase doc: `configs/apps/<app>/specs/` (`<app>-spec.md`, `PHASES.md`, `_generated/`)

This station is listed here so the assembly line map stays **end-to-end** from customer need to shipped code.

**Next station:** **`../03-registry/`** — register agents, tools, queues, and workflow (who and what may run on the line). Stack IR **prompt modules** live under **`factory/00_product_definitions/app_stack/`** (consumed by **`../06-gates/gates/app-blueprint-config.ts`**). Then **`../06-gates/`** runs wizards that **read** those trees (e.g. **`mfg app stack`**).
