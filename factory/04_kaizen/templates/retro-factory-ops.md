# Retro — factory / line ops (~20 min)

Use after a **milestone** (green `validate factory`, release attempt, or painful incident). Focus on **the system that builds software**, not a single app feature.

## Attendees

Facilitator + whoever touched **`mfg`**, registries, CI, or deploy gates this cycle.

## Agenda

1. **Facts (5 min)** — What did we run? (`check`, `validate factory`, deploy tier, telemetry day)
2. **What went well (5 min)** — Start / continue
3. **Pain (5 min)** — Stop / fix next; one thread at a time
4. **One commitment (5 min)** — Exactly **one** kaizen item for the next cycle (copy `improvement-item.template.md` → `../backlog/` or open a task)

## Outputs

- [ ] One item in **`../backlog/`** or **`task-queue.json`**
- [ ] Optional: QMS inbox stub under **`factory/06_knowledge_base/qms_docs/inbox/`** if your process requires evidence

## Anti-patterns

- More than **one** committed improvement without finishing the last
- Retro with no link to a **signal** (command output or log path)
